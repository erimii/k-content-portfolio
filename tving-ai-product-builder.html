MEASURE

기능 사용을 이벤트로 먼저 정의

decoder.open, 탭 탐색, 완료 행동과 유입 링크를 추적해 기능 반응과 전환 경로를 관리자 대시보드에서 확인하도록 만들었습니다.

BUILD

제품과 운영 도구를 함께 구축

모바일 영상 피드, Scene Decoder, 콘텐츠 검수, 데일리 지표, 세션 리뷰, 푸시 운영까지 사용자 화면과 백오피스를 함께 설계했습니다.

SCALE

데이터의 목적에 따라 저장소 분리

원시 이벤트는 R2, 세션 퍼널은 sessions DB, 일별 집계는 analytics DB로 나누고 배치 ID·검증값·수집 원장으로 재처리 중복을 막았습니다.

DELIVER

검증된 웹을 앱으로 확장

React Native WebView 셸로 웹 자산을 재사용하면서 로그인·푸시·영상 재생은 네이티브 브리지로 보완해 Android 앱 출시까지 완료했습니다.

How I Build

제품을 끝까지
작동시키는 세 원칙.

AI의 새로움보다 사용자의 문제, 데모보다 반복 사용, 완벽한 첫 답보다 빠른 검증을 중요하게 생각합니다.

문제부터 한 문장으로

기술을 고르기 전에 사용자, 반복 행동, 바뀌어야 할 결정을 먼저 명확히 합니다.

실패를 격리 가능한 구조로

외부 API와 AI 호출은 실패를 전제로 두고 캐시·재시도·대체 경로·관측 지점을 설계합니다.

지표가 다음 개발을 결정하게

출시를 완료로 보지 않고, 행동 데이터를 통해 가설을 확인하고 우선순위를 다시 정합니다.
